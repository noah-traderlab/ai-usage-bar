## 1. 概要

### 1.1 目的
Codex と Claude の利用枠（残り％）とトークン使用量を、タスクバー／タスクトレイで常に確認できるようにします。また、Claude Code・Codex で「いつ・誰が・どのフォルダで・何を依頼したか」を、PC内のログから一覧で確認・書き出しできるようにします。

さらに**チーム機能**として、導入した人（マスター）がメンバーをメールアドレスで登録し、各メンバーのAI利用量・費用（プラン月額と API 換算の目安）・作業内容・依頼文を、表で確認・管理できます（「7A. チーム機能」）。

### 1.2 前提と範囲
- 利用者本人の Windows アカウントで動くローカルアプリです。**既定ではインターネットに接続しません**。例外は、マスターが任意で有効にする「AI提案」機能だけで、有効にした場合に限りマスターのAPIキーで Anthropic API に集計サマリー（数値と傾向。依頼文の本文は含まない）を送信します（既定オフ・ポリシー `DisableAiSuggest=1` で禁止可）。
- チーム機能を使う場合だけ、組織が用意した**共有フォルダ**（社内ファイルサーバー、OneDrive / SharePoint の同期フォルダなど）に、暗号化した報告ファイルを書き込みます。共有フォルダの通信・同期は Windows や OneDrive などの既存の仕組みが行います。
- 本アプリに ChatGPT・Codex・Claude・Claude Code は含まれていません。利用者のPCにインストール済みのアプリ・CLIと、それらが保存したログを読み取ります。
- ChatGPT・Claude の通常チャットは、PCに履歴が残らないため対象外です。

### 1.3 動作環境
| 項目 | 内容 |
|---|---|
| OS | Windows 10 / 11（実機確認は Windows 11 Home 26200。Windows 10 は未確認） |
| ランタイム | .NET Framework 4.7.2 以上（推奨 4.8。Windows 10 1903 以降・Windows 11 は 4.8 を標準搭載）。4.7.2 未満では起動せず、更新を案内（PBKDF2-SHA256 に 4.7.2 が必要） |
| 権限 | 一般ユーザー（`asInvoker`。管理者権限を要求しない） |
| 外部ライブラリ | なし（.NET Framework 標準ライブラリのみ） |
| インストール | 不要（exe 1ファイル）。インストーラー・サービス・ドライバーなし |

## 3. 構成

```
┌──────────────── AI Usage Bar（利用者の権限で1プロセス） ────────────────┐
│ UIスレッド：タスクバー／トレイ／画面描画、1分・n分ごとのタイマー            │
│ 取得スレッド：Codex CLI との JSON-RPC（stdin/stdout）                     │
│ 集計スレッド：ログの差分読み取り（優先度：低）                              │
└──────┬──────────────────────┬─────────────────────────┬─────────────┘
       │起動（n分ごと、約1秒）   │読み取り（1分ごと）          │読み書き
       ▼                      ▼                         ▼
 Codex CLI（app-server）   Claude Desktop の利用枠履歴    %LOCALAPPDATA%\AIUsageBar
   │                       Claude Code / Codex のログ    （設定・集計キャッシュ）
   ▼
 OpenAI（利用状況の取得。Codex CLI が利用者の認証で通信）
```

- 既定ではネットワーク通信を行いません（唯一の例外は任意機能「AI提案」。7A.8C 参照）。
- 常駐中の処理：「Claude・作業ログの確認間隔」（1／5／10／15／30／60分、初期値1分）ごとに Claude の利用枠履歴とログの追記分だけを読みます。Codex は「Codexの更新間隔」（1／5／10／15／30／60分、初期値5分）ごとに CLI を起動して取得します。どちらも設定画面で変更できます。

## 4. 読み取るデータ

| # | 対象 | 既定のパス | 読む内容 | 頻度 |
|---|---|---|---|---|
| R1 | Claude Desktop の利用枠履歴 | `%APPDATA%\Claude\plan-usage-history.json`、または Microsoft Store 版 `%LOCALAPPDATA%\Packages\Claude_*\LocalCache\Roaming\Claude\plan-usage-history.json` | 記録時刻、5時間・7日間の使用率、組織ID（最新の記録を選ぶためだけに使用） | 1分ごと |
| R2 | Claude Code の会話ログ | `%USERPROFILE%\.claude\projects\**\*.jsonl` | 応答ごとのトークン数、メッセージID・リクエストID（重複除去用）、時刻、セッションID、作業フォルダ、入力経路、モデル名、タイトル。**依頼文は詳細ログの表示・書き出しのときだけ**該当行を読む | 1分ごと（追記分のみ） |
| R3 | Codex のセッションログ | `%USERPROFILE%\.codex\sessions\**\*.jsonl`、`archived_sessions`（`CODEX_HOME` 指定時はそのフォルダ） | 応答IDごとのトークン数、時刻、セッションID、作業フォルダ、起動元、親セッション、モデル名。依頼文は R2 と同様に表示時のみ | 1分ごと（追記分のみ） |
| R4 | Codex のスレッド名 | `%USERPROFILE%\.codex\session_index.jsonl` | スレッドID・スレッド名 | 詳細ログの表示時 |
| R5 | Claude Code のアカウント表示名 | `%USERPROFILE%\.claude.json` | `oauthAccount` のメールアドレス・表示名・組織名・アカウントIDのみ | 詳細ログの表示時 |
| R6 | Codex のアカウントと利用枠 | Codex CLI（app-server）の応答 | 利用枠、リセット日時、プラン、日別トークン数、アカウント種別とメール | 設定間隔ごと |
| R7 | インストールの検出 | `%LOCALAPPDATA%\Packages\`、`%LOCALAPPDATA%\OpenAI\Codex`、PATH など | フォルダ・ファイルの有無のみ | 設定画面の表示時 |
| R8 | 組織ポリシー | `HKLM\SOFTWARE\Policies\AIUsageBar`、`HKCU\SOFTWARE\Policies\AIUsageBar` | DWORD 値 | 起動時 |
| R10 | チーム設定・報告（チーム参加時） | 共有フォルダの `AIUsageBar-Team\team.json`、`team-key.enc`（マスターのみ）、`reports\*.aiubr`（マスターのみ） | チーム設定（署名を検証）、各メンバーの報告（マスターが復号・署名を検証） | 5分ごと・チーム画面の表示時 |
| R9 | 表示テーマ | `HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize` の `AppsUseLightTheme` | ライト／ダーク | 画面表示時 |

**読まないもの**：`%USERPROFILE%\.codex\auth.json`、`%USERPROFILE%\.claude\.credentials.json`、API キー・OAuth トークン類、ブラウザーのデータ、Claude Desktop の Cookie・IndexedDB・Local Storage、クリップボード、他ユーザーのプロファイル。

**読み取りの範囲の制限**：
- 表示時に依頼文を読むのは、R2・R3 のフォルダ配下にあるファイルだけです。キャッシュが改ざんされて別のファイルを指していても読みません。
- 1行の読み取りには上限があります（応答行 32MB、依頼行 256KB、その他 64KB〜4MB）。上限を超えた行は読み飛ばし、件数だけを記録します。
- 集計対象は、更新日時が直近14日以内のファイルだけです。

## 5. 書き込むデータ

保存先：`%LOCALAPPDATA%\AIUsageBar\`（ローミングしないプロファイル領域）。フォルダのアクセス権は、**本人・SYSTEM・Administrators だけ**に設定します（親フォルダからの継承を切ります）。

| # | ファイル | 内容 | 含む個人情報 | 保存期間 |
|---|---|---|---|---|
| W1 | `settings.json` | 表示設定（更新間隔、通知、表示方式など） | なし | 削除するまで |
| W2 | `codex-snapshot.json` | 前回取得した Codex の利用枠・日別トークン・プラン・アカウント種別 | なし（メールアドレスは保存しない） | 取得のたびに上書き |
| W3 | `local-logs-v4.json` | 応答ごとのトークン数と時刻、セッションID、作業フォルダのパス、ログ内の位置（ファイルパスとバイト位置）、入力経路、依頼文の HMAC-SHA256（先頭12バイト、重複判定用） | **作業フォルダのパス**（フォルダ名に顧客名などが含まれる場合あり） | 14日より古い記録は自動削除 |
| W4 | `hash-key.bin` | W3 の HMAC 用に端末ごとに生成した32バイトの乱数鍵 | なし | 削除するまで |
| W5 | `error.log` | 予期しない例外の内容（スタックトレース） | ファイルパスを含む場合あり | 1MB を超えたら先頭から作り直す |
| W6 | `codex-work\` | Codex CLI を起動するための空の作業フォルダ | なし | — |
| W7 | 書き出したファイル | 利用者が保存ダイアログで選んだ場所。詳細ログ（依頼文を含む）または仕様・セキュリティ情報 | **依頼文、メールアドレス、パス** | 利用者が管理 |
| W9 | `team-local.json` | チーム参加状態：共有フォルダのパス、チームID、確認済みのチーム公開鍵と世代、見た最新の版、同意した範囲、このPCの署名鍵（DPAPI）、チーム秘密鍵（マスターのみ・DPAPI）、申告した名前・メール、前回の報告内容のハッシュ | **メールアドレス（申告分）** | チームから抜けるまで（壊れていた場合は `.corrupt-日時` に退避） |
| W10 | `team-pins.json`（マスターのみ） | 報告してきたPCのチーム確認コード、承認時のメールアドレスの組、承認状態、最新の報告日時 | **メールアドレス** | 180日報告のないPCは自動削除 |
| W11 | 共有フォルダ `AIUsageBar-Team\` | `team.json`（チーム設定：メンバーの名前・メール・権限・閲覧範囲・単価は署名付きで**暗号化なし**。契約プラン・月額・メモはチーム公開鍵で**暗号化**）、`team-key.enc`（パスフレーズで暗号化したチーム秘密鍵）、`reports\<PC識別子>.aiubr`（暗号化した報告） | `team.json` に**メンバーの名前・メール**（プラン・月額・メモは暗号化）。報告は暗号化 | 組織が管理 |
| W12 | `friends.json` | フレンド機能の設定：このPCの識別子（乱数）、共有フォルダのパス、表示名、オン／オフ | 表示名 | 削除するまで |
| W13 | 共有フォルダ `AIUsageBar-Friends\<識別子>.json` | 表示名、Claude（5時間・週間）と Codex の残り％、Codex のリセット時刻、更新時刻（**暗号化なし**。フォルダを共有した相手が読める） | **表示名**（メールアドレス・トークン数・作業内容・依頼文は含まない） | オフにすると削除。7日以上更新のないファイルは表示しない |

## 6. 通信と子プロセス

### 6.1 ネットワーク
| 項目 | 内容 |
|---|---|
| 本アプリ自身の通信 | 既定では**なし**（待ち受けポートもなし）。唯一の例外は任意機能「AI提案」で、有効化してボタンを押したときだけ `https://api.anthropic.com/v1/messages` へ HTTPS 送信します（7A.8C。既定オフ・`DisableAiSuggest=1` で禁止可） |
| テレメトリ・利用統計 | なし |
| 自動更新 | なし |
| ブラウザーで開くURL | 利用者が「Claudeで使用状況を開く」を押したときだけ `https://claude.ai/settings/usage`（固定値） |
| 子プロセスの通信 | Codex CLI が、利用者のログイン情報で OpenAI から利用状況を取得します。宛先・プロキシ・証明書の扱いは Codex CLI の設定に従います。生成リクエスト（モデルの呼び出し）は送りません |
| 共有フォルダ（チーム機能） | 本アプリはファイルの読み書きだけを行います。ファイルサーバー（SMB）や OneDrive / SharePoint との通信は Windows・同期クライアントが行います。UNC パス（`\\サーバー\共有`）は、利用者がチームの共有フォルダとして明示的に選んだ場合に限り使います |

### 6.2 Codex CLI の起動
| 項目 | 内容 |
|---|---|
| 探索順 | ① PATH（絶対パスの項目のみ）の `codex.exe` / `codex.cmd` → ② `%USERPROFILE%\.local\bin\codex.exe` → ③ `%APPDATA%\npm\codex.cmd`（npm 版は同梱の `codex.exe` を直接使用）→ ④ Codex アプリ同梱の `%LOCALAPPDATA%\OpenAI\Codex\bin\*\codex.exe`（最新のもの） |
| コマンドライン | `"<codex.exe>" -c analytics.enabled=false app-server` |
| 作業フォルダ | `%LOCALAPPDATA%\AIUsageBar\codex-work`（空フォルダ）。環境変数 `GIT_CEILING_DIRECTORIES` を設定し、git が上位フォルダのリポジトリ設定を読まないようにする |
| 送る要求（JSON-RPC） | `initialize`、`account/rateLimits/read`、`account/usage/read`、`account/read`（`refreshToken: false`） |
| 送らない要求 | スレッド作成・ターン開始など、モデルを呼び出す要求は一切送りません |
| 古い CLI への対応 | 追加パラメーターを受け付けない版にはパラメーターなしで再試行。利用枠の取得自体に非対応の版では、Codex の更新を案内 |
| 終了処理 | 標準入力を閉じて3秒待ち、残っていれば `%SystemRoot%\System32\taskkill.exe /T /F` で子プロセスごと終了 |
| タイムアウト | 45秒 |
| 1回の所要時間 | 実測 約0.8秒 |
| 無効化 | ポリシー `DisableCodexFetch=1` で起動しない |

## 7. セキュリティ設計

### 7.1 実装している対策
| 脅威 | 対策 |
|---|---|
| DLL の植え込み（exe を Downloads 等に置いた場合） | 起動直後に `SetDefaultDllDirectories(LOAD_LIBRARY_SEARCH_SYSTEM32)` と `SetDllDirectory("")` を呼び、P/Invoke 先を `DefaultDllImportSearchPaths(System32)` に限定 |
| 同名の exe の植え込み | `explorer.exe`、`taskkill.exe`、`cmd.exe` を `%SystemRoot%` の絶対パスで起動。PATH の相対パス項目は Codex 探索で無視 |
| コマンドインジェクション | 子プロセスの引数はすべて固定文字列＋ファイルシステムから得たパス。ログ由来の文字列はプロセス引数に渡さない（フォルダを開く場合は実在確認後のパスのみ） |
| git の設定ファイル経由のコード実行 | Codex CLI を専用の空フォルダで起動し、`GIT_CEILING_DIRECTORIES` で上位探索を止める |
| キャッシュの改ざん | 依頼文を読むファイルを、Claude Code・Codex のログフォルダ配下に限定。壊れたキャッシュは捨てて読み直す |
| 巨大ファイル・不正なJSON | 1行ごとの上限、JSON の入れ子の深さ上限（256）、解析失敗は件数だけ記録して読み飛ばし |
| 書き出しファイルの悪用 | CSV：`= + - @` やタブ・改行で始まるセルの先頭に `'` を付けて数式にならないようにする。Markdown：`<` `>` を実体参照に置き換えて HTML として解釈されないようにする |
| 保存データの覗き見（同じPCの他の利用者） | 保存先のアクセス権を本人・SYSTEM・Administrators に限定 |
| 依頼文の推測 | 重複判定には端末ごとの乱数鍵を使った HMAC-SHA256 を使い、依頼文そのもの・素のハッシュを保存しない |
| 権限の昇格 | `asInvoker`。管理者権限・サービス・スケジュールタスクを使わない |
| 他プロセスからの操作 | 二重起動防止の名前付きオブジェクトは `Local\`（同じログオンセッション内）で、ユーザー SID＋GUID の名前と本人だけのアクセス権。外部から受け付ける操作は「画面を開く」の合図だけ |
| 子プロセスの残留 | Codex CLI をジョブオブジェクト（`KILL_ON_JOB_CLOSE`）に入れ、アプリが強制終了されても OS が終了させる |
| ネットワーク共有経由の認証情報送信 | UNC パス（`\\サーバー\…`）には接続しない |
| 不正なデータによる停止 | 数値・時刻の範囲チェック。読み取りの失敗は「未取得」表示にして動作を続ける |
| 常用場所 | Downloads・デスクトップ・一時フォルダからはログイン時起動を登録させず、「推奨の場所へ移動」を案内 |
| 通知・ツールチップからの漏えい | 表示するのは残り％と枠の名前のみ。依頼文やメールアドレスは出さない |

### 7.2 組織ポリシー（管理者向け）
グループポリシーの基本設定や Intune の構成プロファイルで、次のレジストリ値（DWORD）を配布できます。`HKLM` と `HKCU` の `SOFTWARE\Policies\AIUsageBar` を読み、**どちらかで 1 なら有効**です（より厳しい方を採用）。`Policies` キーは通常ユーザーが変更できないため、利用者は解除できません。有効な項目は、設定画面で「組織のポリシーで管理されています」と表示され、操作できなくなります。

| 値の名前 | 1 にしたときの動作 |
|---|---|
| `DisableActivityLog` | 詳細ログ（セッション・入力の一覧）を使わせない。書き出しもできない |
| `HidePromptText` | 依頼文を画面にも書き出しにも出さない（タイトルも依頼文から作らない） |
| `DisableExport` | Markdown / CSV の書き出しを禁止 |
| `DisableCodexFetch` | Codex CLI を起動しない（Codexの利用枠・日別トークン・アカウントを取得しない） |
| `DisableStartupRegistration` | ログイン時起動を登録させない（既存の登録は起動時に削除） |
| `DisableTeamSharing` | チーム機能（共有フォルダへの報告・マスター機能）を無効 |
| `TeamMaxScope` | チームに共有できる範囲の上限（0：利用量のみ／1：作業の概要まで／2：依頼文まで） |

設定例（管理者の PowerShell）：
```powershell
New-Item -Path 'HKLM:\SOFTWARE\Policies\AIUsageBar' -Force | Out-Null
Set-ItemProperty -Path 'HKLM:\SOFTWARE\Policies\AIUsageBar' -Name HidePromptText -Value 1 -Type DWord
Set-ItemProperty -Path 'HKLM:\SOFTWARE\Policies\AIUsageBar' -Name DisableExport  -Value 1 -Type DWord
```

### 7.3 個人情報・機微情報の扱い
| 情報 | 取得元 | 画面表示 | キャッシュ保存 | 書き出し | 無効化の方法 |
|---|---|---|---|---|---|
| 依頼文（プロンプト） | R2・R3 | 詳細ログ | しない（HMACのみ） | する | `HidePromptText`／設定「依頼文を表示」 |
| セッションのタイトル | R2・R4 | 詳細ログ | しない | する | `DisableActivityLog`（依頼文から作るタイトルは `HidePromptText` でも出さない） |
| 作業フォルダのパス | R2・R3 | 詳細ログ | する | する | `DisableActivityLog` |
| メールアドレス | R5・R6 | 利用枠・詳細ログ | しない | する | `DisableCodexFetch`（Codex）、`DisableActivityLog`（Claude Code） |
| Windows ユーザー名・PC名 | OS | 詳細ログ | しない | する | `DisableActivityLog` |
| トークン数・利用枠 | R1・R2・R3・R6 | すべて | する | する | — |

「入力者」は、ログがこのPCの利用者プロファイルにあることに基づく表示（Windowsユーザー名@PC名）です。「アカウント」は現在ログイン中の情報です。Claude Code のリモート接続で別アカウントが記録されている場合だけ、そのアカウントIDを表示します。**過去に別アカウントで行った作業を厳密に区別するものではありません**。監査証跡として使う場合はこの点にご注意ください。

## 7A. チーム機能（マスター／一般ユーザー）

### 7A.1 役割と見える範囲
| 役割 | できること | 見えるもの |
|---|---|---|
| マスター | チームの作成、メンバー登録（名前・メールアドレス・権限・閲覧範囲・契約プランと月額）、単価と為替の設定、PC の承認・報告の削除、鍵の更新、表の CSV 出力 | 全メンバーの利用量・費用。各メンバーについて「閲覧範囲」と「本人の同意」と「組織ポリシー」の最も狭い範囲までの作業内容・依頼文 |
| 一般ユーザー | チームへの参加、共有範囲への同意と変更、退出 | 自分の利用状況だけ（他のメンバーの報告は暗号化されていて読めない） |

閲覧範囲は3段階です。

| 範囲 | 報告に含める内容 |
|---|---|
| 利用量のみ | 日別・ツール別・モデル別のトークン数（入力・出力・キャッシュ・推論）、残り枠、Codex のサービス集計値、PC名・Windowsユーザー名・メールアドレス |
| 作業の概要まで | 上記＋直近14日のセッション（タイトル、作業フォルダ、時間帯、入力経路、モデル、依頼件数、トークン数）。タイトルは AI・利用者が付けたもの／Codex のスレッド名だけで、依頼文からは作らない |
| 依頼文まで | 上記＋直近14日の依頼文の本文（1件 8,000 文字まで） |

**実際に共有する範囲 ＝ マスターの設定・本人の同意・組織ポリシー（`TeamMaxScope`、`HidePromptText`、`DisableActivityLog`）のうち最も狭いもの**です。マスターが範囲を広げても、本人が同意するまでは同意済みの範囲だけを共有し、本人の画面に同意を求める表示が出ます。

### 7A.2 データの流れ
```
メンバーのPC（一般ユーザー／マスター）                      共有フォルダ AIUsageBar-Team\
  ローカルの記録 ─集計→ 報告（範囲で絞る）                    team.json      … マスターが署名
      │ ① チーム公開鍵で暗号化（RSA-OAEP＋AES-256＋HMAC）     team-key.enc   … パスフレーズで暗号化した秘密鍵
      │ ② このPCの鍵で署名（RSA-PSS）                          reports\*.aiubr … 暗号化された報告
      └──── 内容が変わったとき（最短5分・変化がなくても1時間に1回）書き込み ──→
マスターのPC
  ③ team.json の署名を確認  ④ 報告の署名を確認・PCの鍵とメールアドレスを記録（初回・変更時は承認待ち）
  ⑤ チーム秘密鍵（DPAPIで保護）で復号 → メールアドレスでメンバーと結び付けて表示（複数のメンバーに一致する報告は集計しない）
```

### 7A.3 暗号方式
| 用途 | 方式 |
|---|---|
| チーム鍵 | RSA 3072bit（`RSACng`） |
| チーム設定・鍵更新の署名 | RSA-PSS / SHA-256（キーを辞書順に並べた JSON を署名） |
| PC の署名鍵 | RSA 2048bit（PC ごとに生成、DPAPI で保護） |
| 報告の暗号化 | 64バイトの乱数鍵（AES-256 用 32＋HMAC 用 32）を RSA-OAEP-SHA256 で包み、本文を AES-256-CBC（乱数 IV）で暗号化、ヘッダー・IV・暗号文をそれぞれ長さ付きで連結して HMAC-SHA256（暗号化してから MAC）。MAC は定数時間で比較 |
| 報告の長さ | 暗号化の前に 64KB／256KB／1MB／4MB の段階まで空白で埋める（ファイルサイズから共有範囲・作業量を推測しにくくする）。上限 8MB |
| 契約プラン・メモ | メンバーごとのプラン名・月額・メモを、報告と同じ方式でチーム公開鍵により暗号化して `team.json` に格納 |
| チーム秘密鍵の共有 | PBKDF2-SHA256（60万回固定、32バイトの乱数ソルト）で鍵を作り、同じ AES-256-CBC＋HMAC-SHA256 で暗号化。鍵ファイルには「チームID＋鍵の世代」を用途として記録し、別のチーム・別の世代の鍵ファイルや、反復回数を書き換えたファイルは受け付けない |
| 公開鍵の受け入れ | 公開指数 65537、チーム鍵 3072〜4096bit、PC の鍵 2048〜4096bit だけを受け入れる |
| チーム確認コード | 「用途名・n・e」を長さ付きで連結した SHA-256 の先頭 128bit（32桁、4桁ずつ区切り） |
| PC 内の保存 | DPAPI（`CurrentUser`、用途ごとの追加エントロピー） |
| 乱数 | `RandomNumberGenerator`（OS の暗号学的乱数） |

すべて .NET Framework 標準の暗号ライブラリで、独自の暗号アルゴリズムは使っていません。

### 7A.4 信頼の仕組み
| 仕組み | 内容 |
|---|---|
| 参加時の鍵の確認 | マスターから共有フォルダとは別の手段（対面・電話・社内チャット等）で伝えられた「チーム確認コード」（32桁）を、**参加する本人が入力**。共有フォルダのチームと一致しない場合は参加できない（「はい」を押すだけの確認にはしない）。また、画面で確認したチームと参加の瞬間に読み直したチームが違えば参加しない。以後はその鍵だけを信頼（固定） |
| チーム設定の検証 | 報告のたびに `team.json` の署名を固定した鍵で検証。署名がない・鍵が違う・改ざんされた設定では**報告しない** |
| 巻き戻し防止 | 一度見た版より古い `team.json`、固定した世代より古い鍵は拒否 |
| 鍵の更新 | `team.json` に鍵の更新履歴を持ち、各世代の新しい鍵に「1つ前の鍵による署名」を付ける。メンバーの PC は、固定した世代から現在の世代まで署名を1つずつたどれた場合だけ新しい鍵に切り替える（間の世代を見逃していても追従）。旧鍵のマスター権限は破棄 |
| PC の承認 | マスターは報告してきた PC の鍵・メールアドレスの組・最新の報告日時を記録し、**初めての PC、鍵が変わった PC、メールアドレスが変わった PC は承認するまで集計に含めない**。承認画面には PC のチーム確認コードを表示し、本人の画面（「チーム」タブの「このPCの確認コード」）と照合できる |
| 報告の差し戻し | 以前の正しい報告ファイルに戻されたもの（作成日時が記録より古い）と、作成日時が10分以上未来の報告は受け付けない |
| メンバーとの結び付け | Claude・Codex から検出したメールと申告メールで照合。**別々のメンバーに一致する報告はどちらにも集計せず**、管理画面に件数を表示 |
| マスター権限 | 「チーム設定でマスターに指定されている」かつ「チームのパスフレーズで秘密鍵を解除した」PC だけ。パスフレーズを知っていてもマスターに指定されていなければ有効にできない。権限の実質的な境界はパスフレーズ（鍵）で、アプリの表示上の制御ではない |
| マスターの解除 | マスターを一般ユーザーにする・削除する操作は、**鍵の更新（新しいパスフレーズの設定）と同時にしか保存できない**。外された人の PC は、次にチーム設定を読んだときに保存済みのチーム秘密鍵を消す |
| 同時編集 | 他のマスターが先に保存した場合は上書きせず、読み込み直しを求める |
| 同意の縮小・退出・ポリシー | 本人が共有範囲を狭めた、チームから抜けた、`DisableTeamSharing` が配布された場合は、共有フォルダにある自分の報告を**すぐに削除**（ポリシーは起動中も1分ごとに読み直す） |
| 他の PC から届いた文字列 | 名前・メール・タイトル・フォルダ名などは、制御文字・文字の向きを変える記号・ゼロ幅文字を除き、長さを制限してから表示・CSV 出力 |
| 参加情報の破損 | `team-local.json` が壊れていた場合、黙って初期化せずにエラーを表示し、参加し直すときに壊れたファイルを退避 |

### 7A.5 脅威と対策
| 脅威 | 対策 | 残るリスク |
|---|---|---|
| 一般ユーザーが他人の報告を読む | 報告はチーム公開鍵で暗号化。秘密鍵はマスターだけ。長さは段階的にそろえ、内容が変わらなければ書き込まない | 共有フォルダのファイル名（PC識別子）・おおよその更新時刻・サイズの段階は見える |
| 一般ユーザーが他人の契約プラン・月額を見る | `team.json` 内で暗号化 | 名前・メール・権限・閲覧範囲は見える（報告の検証に必要なため） |
| 一般ユーザーが `team.json` を書き換えて自分をマスターにする／範囲を変える | 署名検証で拒否。マスター権限にはパスフレーズも必要 | 書き換えられた間は報告が止まる（可用性） |
| 攻撃者が自分の鍵でチーム設定を作り直し、報告を盗む | 参加時に本人が確認コードを入力して照合し、その鍵に固定。以後は前の鍵の署名がない鍵の変更を拒否 | 確認コードを共有フォルダと同じ経路（改ざんされ得る経路）で受け取った場合 |
| 他人になりすました報告・他人の報告の上書き | PC ごとの署名鍵、マスターによる PC の承認、メールアドレスの変更検知、あいまいな一致の除外、差し戻し・未来日時の拒否 | 共有フォルダに書き込める人は報告ファイルを**削除**できる。マスターが確認せずに承認した場合 |
| マスターを外された人が引き続き読む | 外す操作と鍵の更新を必ず同時に行い、外された PC からは秘密鍵を削除 | 更新前に読んだ・保存したデータは取り消せない |
| パスフレーズの漏えい・総当たり | 12文字以上かつ6種類以上の文字、PBKDF2-SHA256 60万回。漏えい時は鍵の更新 | 推測しやすいパスフレーズ |
| 不正な共有ファイルによる処理の妨害 | 設定 2MB・鍵ファイル 64KB・報告 9MB・報告数 500件・メンバー 5,000人などの上限、鍵長の上限、反復回数の固定 | 共有フォルダを壊されると報告が止まる（可用性） |
| マスターの PC の乗っ取り | 秘密鍵は DPAPI で本人のアカウントにだけ保存 | 乗っ取られた場合は全メンバーの報告を読まれる |
| 過度な監視（依頼文の閲覧） | 3段階の閲覧範囲、本人の同意、組織ポリシーで上限、本人の画面に共有範囲を常に表示 | 下記「7A.7 導入時の注意」 |

### 7A.6 費用の表示
| 項目 | 内容 |
|---|---|
| プラン月額 | マスターがメンバーごとに契約プラン名と月額（円）を登録。実際の費用として表示 |
| API 換算（目安） | 日別・モデル別のトークン数 × 単価表（100万トークンあたりの米ドル）× 為替。Claude はキャッシュ読み取り・キャッシュ作成（5分／1時間）を区別。Codex はキャッシュ済み入力と通常の入力を区別 |
| 単価の初期値 | Claude のモデルは Anthropic API の公式料金（2026年6月時点の資料）。OpenAI のモデルは確かな資料がないため未設定とし、マスターが入力。未設定の分は金額に含めず「一部単価未設定」と表示 |
| 注意 | API 換算は「使った量を API で買った場合の目安」で、サブスクリプション契約の実際の請求額とは異なる |
| 期間 | 今日・直近7日・直近30日・今月・先月。日別の集計は各 PC に 400 日保存（作業内容・依頼文は直近14日のみ） |

### 7A.6B 招待・参加・自動集計
| 項目 | 内容 |
|---|---|
| メンバー登録 | マスターは「メンバーを追加（メール）」で、メールアドレスを1行に1人（名前付き・Excel/Slack からの貼り付けにも対応）まとめて一般ユーザーとして登録できる |
| 招待メール | 「招待を送る」画面から、(a)このアプリから直接 SMTP 送信、(b)既定のメールアプリ（`mailto:`）、(c)ブラウザの Gmail（作成画面URL）、(d)本文コピー（Slack 用）を選べる。(a)は送信サーバー・アドレス・送信用パスワード（Gmail/Outlook は「アプリパスワード」）を設定すると、宛先を入れて1クリックで送信。パスワードは DPAPI で本人のWindowsアカウントだけが復号できる形で `mail.json` に保存し、設定した SMTP サーバー以外へは送らない。(b)(c)は URL を OS に渡すだけ（アプリは送信しない） |
| 招待メールの本文 | 簡素な本文に「参加リンク」（`aiusagebar:join?c=…`）と「招待コード」（`AIUB-INVITE-1:…`）を記載。いずれも共有フォルダの場所・チーム名・チーム確認コードだけで秘密情報は含まない |
| 参加リンク | アプリを導入済みのPCでリンクを開くと参加画面が開く。URL スキーム `aiusagebar:` を、このユーザーのレジストリ（`HKCU\Software\Classesiusagebar`）に、安全な場所にある exe のときだけ登録する。起動時に受け渡しファイル（`pending-invite.txt`、60秒以内のもののみ）を介して参加画面へ渡す。リンクが使えない場合は招待コードを貼り付けて参加できる |
| 招待コード | 共有フォルダの場所・チーム名・チーム確認コードだけを Base64URL で1つの文字列にしたもの（`AIUB-INVITE-1:`）。秘密情報は含まない。参加画面に貼り付けると共有フォルダと確認コードが自動で入る |
| 参加時の同意 | 本人が「すべて（依頼文の本文を含む）の共有」に同意した場合のみ参加できる（同意しない選択では参加不可）。実際に共有される範囲は、マスターの閲覧範囲設定・組織ポリシーで狭められる |
| 自動集計 | Claude Code・Codex に実際にログインしているメールアドレスが、登録メンバー1人だけに一致する報告は、マスターの承認なしで集計する（`autoApproveByLogin`。既定オン、チーム設定で切替可）。本人が入力しただけのメール、2人のメンバーに一致する報告、鍵・メールが変わったPC、マスターが承認を取り消したPCは承認待ちになる |

### 7A.7 導入時の注意（プライバシー・労務）
- 依頼文には、業務情報・顧客情報・個人的な内容が含まれることがあります。「依頼文まで」を使う場合は、**利用目的・閲覧者・保存期間を社内規程で定め、対象者に事前に周知**してください。本アプリは本人の同意を取る画面を備えていますが、就業規則・個人情報保護規程上の手続きの代わりにはなりません。
- 閲覧は必要最小限にしてください。組織として依頼文の閲覧を認めない場合は、ポリシー `TeamMaxScope=1`（作業の概要まで）または `0`（利用量のみ）を配布してください。
- 共有フォルダは、チームのメンバーだけがアクセスできる場所にし、社外共有を無効にしてください。`team.json` にはメンバーの名前・メールアドレス・権限・閲覧範囲が暗号化されずに入ります（契約プラン・月額・メモは暗号化）。
- 報告の同意画面は、PC名・Windowsユーザー名・メールアドレスも共有されることを明示します。同意する範囲の初期値は「利用量のみ」です。
- マスターの交代・退職時は、管理画面の「マスターを外す（鍵を更新）」を使ってください（鍵の更新なしでは外せません）。
- マスターが依頼文を CSV に書き出すと、ファイルは暗号化されずアプリの管理外になります（書き出し前に警告を表示。`DisableExport=1` で禁止、`HidePromptText=1` でマスターの画面からも依頼文タブを外します）。

### 7A.8 組織ポリシー（チーム機能）
| 値の名前 | 動作 |
|---|---|
| `DisableTeamSharing`（1） | チームの作成・参加・報告・マスター機能をすべて無効 |
| `DisableAiSuggest`（1） | AI提案（Anthropic API への集計サマリー送信）を無効（ボタンを出さない） |
| `DisableFriends`（1） | フレンドの残り枠（共有フォルダへの書き込み・読み取り）を無効 |
| `TeamMaxScope`（0／1／2） | 共有できる範囲の上限（0：利用量のみ、1：作業の概要まで、2：依頼文まで）。HKLM と HKCU の両方にある場合は狭い方 |

### 7A.8B AI活用ダッシュボード（上層部・部門長向け）
チーム管理画面の「ダッシュボード（上層部向け）」から開く。取得済みのデータだけを使い、費用にとどまらず「AIで何をしているか・誰が使いこなしているか・どう浸透させるか」を1画面で示す。

| 要素 | 内容 |
|---|---|
| KPI | 活用しているメンバー数（利用者/対象）、AI力の平均スコア、依頼数、AIが生成した量（出力トークン）、API換算コスト（目安）・プラン月額合計 |
| AI力ランキング | メンバーごとの「AI活用度スコア（0–100）」とレベル（AIマスター／活用中／発展途上／未活用）、稼働日数・依頼数・トークン・費用・使用ツール |
| サマリー・次の一手 | 取得データからの気づきと提案（例：使いこなし層をAI特務・講師役に／未活用者へのフォロー／活用の偏り／片方のツールのみ／1依頼あたりの費用）。CSV にも出力 |
| 日別トークン | 期間内の日別トークン（Claude Code ＋ Codex の積み上げ棒グラフ） |
| スタートライン（顧客別基準値） | 顧客のAI導入段階に応じた目標を設定すると、KPI（活用率・平均AI力）に目標と達成状況、ランキングに目標ライン・達成✓、サマリーに目標との差分を相対表示（7A.8E） |
| スコアの定義 | 稼働日数・依頼数・トークン量・ツール幅・モデル幅の重み付き合計（依頼数が取れない「利用量のみ」のメンバーはトークン量で補完）。**量・頻度・幅の目安であり、作業の質や人事評価そのものではない**旨を画面に明示 |
| 描画 | 外部ライブラリを使わず GDI+ で描画（円・棒・スコアバー） |
| 留意点 | 「何をしているか（依頼数・依頼文）」を見るには、メンバーの閲覧範囲を「作業の概要／依頼文まで」にし、本人の同意が必要。スコアを人事評価に用いる場合は、活動量の一指標にとどめ、単独の根拠にしないこと |

### 7A.8C AI提案（任意・既定オフ）
ダッシュボードの集計から、上層部向けの「現状サマリーと次の一手」を Anthropic の Claude で自動生成する任意機能。**既定はオフ**で、マスターが自分の API キーを設定して初めて使える。

| 項目 | 内容 |
|---|---|
| 送信先 | `https://api.anthropic.com/v1/messages`（HTTPS）。生の HTTP クライアント（.NET の `HttpWebRequest`）で送信し、外部ライブラリは使わない |
| 送るデータ | ダッシュボードの**集計サマリー（数値と傾向、ツールが自動抽出した気づき）**のみ。**依頼文の本文・会話・メールアドレスは送らない**。送信前に内容を画面で確認できる |
| 認証 | マスター自身の Anthropic API キー。DPAPI で本人の Windows アカウントだけが復号できる形で `ai.json` に保存し、他へは送らない |
| モデル | 既定 `claude-opus-5`。`claude-sonnet-5` / `claude-haiku-4-5` に変更可（費用はマスターのキーに課金）。OpenAI 互換の提供元（`baseUrl`＋モデル名）も選べる |
| 実行契機 | マスターがダッシュボードで「AIに提案してもらう」を押したとき。または「定期レポート」（7A.8D）を有効にした場合に、設定した頻度・時刻で自動実行 |
| 無効化 | ポリシー `DisableAiSuggest=1`（HKLM/HKCU）でボタン自体を出さない（定期レポートも動かない） |
| 留意点 | 有効にすると「本アプリは通信しない」という前提から外れる。導入時は、集計サマリーを外部AIに送ることの社内合意（情報の取り扱い規程）を確認すること |

### 7A.8D 定期レポート（任意・既定オフ）
AI提案（7A.8C）を、設定した頻度・時刻で自動生成してタスクトレイに通知する任意機能。**既定はオフ**で、マスターのみ。送るデータ・送信先・無効化ポリシーは 7A.8C と同じ（集計サマリーのみ・依頼文本文は送らない・`DisableAiSuggest=1` で無効）。

| 項目 | 内容 |
|---|---|
| 設定 | ダッシュボードの「定期レポート…」から、頻度（毎日／毎週／毎月）・曜日（毎週）・日（毎月）・時刻（時：分）・対象期間を指定。`ai-schedule.json` に保存 |
| 実行条件 | このPC（マスター）でアプリが常駐しており、指定時刻を過ぎた最初の点検タイミング（常駐タイマー）で実行。同じ日には1回だけ（`lastRunDate` で二重実行を防止）。APIキー未設定なら実行しない |
| 生成物 | `<データフォルダ>\ai-reports\AI活用レポート_yyyy-MM-dd_HHmm.txt`（テキスト）。生成後にタスクトレイへ「AI活用レポートができました」を通知し、クリックで開く |
| 失敗時 | 生成前に実行日を記録するため、失敗しても同日に何度も呼ばない。失敗内容はトレイ通知＋エラーログに記録 |

### 7A.8E スタートライン（顧客別の基準値・任意・既定オフ）
顧客ごとのAI導入状況に合わせて「スタートライン（基準値）」を設定し、ダッシュボードを**目標に対する相対（達成度）**で見せる機能。導入段階に応じてスコアの見え方・目標を変えることで、「今どの段階か」「次に何を目指すか」を上層部が判断しやすくする。

| 項目 | 内容 |
|---|---|
| 設定 | ダッシュボードの「スタートライン…」から、導入段階（導入前／試験導入／一部活用／全社活用）を選ぶと、目標「平均AI力スコア」「活用率」に目安値が入る。個別に調整も可 |
| 段階の目安 | 導入前＝スコア20・活用率30% ／ 試験導入＝35・50% ／ 一部活用＝50・70% ／ 全社活用＝65・90% |
| 相対表示 | KPIに「目標◯%（達成／あと◯pt）」「目標◯点」、AI力ランキングに目標ラインと達成✓、サマリー・次の一手に目標との差分と次段階の提案。AI提案・定期レポートの要約にも基準を添える |
| 保存先 | このPC（マスター）だけに `baseline.json` として保存。**共有フォルダ・署名対象（team.json）には含めない**（メンバーには共有されない） |
| 位置づけ | スコア・目標は活動量の目安であり、人事評価そのものではない（7A.8B と同じ注意）。目標は運用の目安として使う |

### 7A.9 Mac 用チーム参加ツール
Mac の利用者がチームに参加して報告するための、Mac 標準の Python 3 だけで動くツール（追加インストール不要）。マスターの管理画面は Windows 版が担当する。Mac ツールは「参加」「報告」に加え、「フレンドの残り枠」（共有フォルダで残り枠だけを見せ合う・既定オフ）と「リセット通知」（watch 中に macOS 通知・既定オフ）にも対応する（いずれも Windows 版と同じファイル形式・判定）。

| 項目 | 内容 |
|---|---|
| 構成 | `mac/aiusagebar/`（Python パッケージ）。GUI は Tkinter（Mac の Python に同梱）、CLI は `python3 -m aiusagebar join/report/status/watch/leave` |
| 暗号・署名 | Windows 版と同一（RSA-3072 チーム鍵で OAEP-SHA256 封入、AES-256-CBC＋HMAC-SHA256、報告は各 Mac の RSA-2048 鍵で RSA-PSS 署名、正規化 JSON はバイト単位で一致）。外部ライブラリを使わず、AES・RSA・OAEP・PSS を標準ライブラリの範囲で実装 |

| 保存先 | `~/Library/Application Support/AIUsageBar`（参加情報・この Mac の鍵。権限 600＝本人のみ） |
| 通信 | 参加・報告ではインターネットに接続しない（共有フォルダのみ）。マスター側の任意機能「AI提案」だけが Anthropic API に送信する |

| 未確認 | Mac 実機での起動・画面表示・Codex CLI の取得は、この配布時点では Mac 実機で未確認（Windows 上での相互運用検証のみ）。導入時に対象の Mac で「はじめに（Mac）.txt」に沿って確認してください |

### 7A.10 フレンドの残り枠（任意・既定オフ）
友だち・同僚同士で Claude・Codex の残り枠を見せ合う機能。チーム機能（マスターだけが読める暗号化報告）とは別の仕組みで、参加者全員が互いの残り枠を読めます。

| 項目 | 内容 |
|---|---|
| 仕組み | 利用者が選んだ共有フォルダ（OneDrive・Googleドライブ・Dropbox・社内サーバーなど）の `AIUsageBar-Friends\` に、各PCが `<識別子>.json` を書き、他の人のファイルを読む。アプリ自体は通信しない |
| 共有する内容 | 表示名、Claude（5時間・週間）と Codex（5時間・週間）の残り％、Codex のリセット時刻、更新時刻。古い情報・リセット済みの枠は書かない |
| 共有しない内容 | メールアドレス、プラン、トークン数、作業フォルダ、セッション、依頼文 |
| 更新間隔 | 1分ごとに確認し、残り枠が変わったとき、または5分おきに書く。30分以上更新がない人は灰色で「更新なし」と表示 |
| 招待 | 招待コード `AIUB-FRIEND-1:…` はフォルダの場所だけを含む（秘密情報なし）。フォルダの共有自体は各クラウドサービスの共有機能で行う |
| 読み取りの検証 | ファイル名とファイル内の識別子が一致しないもの、16KB を超えるもの、形式が違うもの、7日以上前・10分以上未来の時刻のもの、リンク（再解析ポイント）は無視。表示名は制御文字・方向制御・ゼロ幅文字を除き40文字まで、残り％は0〜100に丸める。最大100人 |
| やめるとき | 設定でオフにすると、共有フォルダから自分のファイルを削除する |
| 注意 | 暗号化・署名はしないため、フォルダに書き込める人は他人の表示名を名乗ったファイルを置ける（実害は表示だけ）。信頼できる相手とだけフォルダを共有する。組織では `DisableFriends` で無効化できる |

## 10. アンインストールとデータ削除

1. チームに参加している場合は、「チーム」タブの「チームから抜ける」で共有フォルダの自分の報告を削除する。
2. 設定で「ログイン時に起動」を OFF にし、画面下の「終了」で終了する。
3. タスクバーのピン留めを外す（右クリック →「タスクバーからピン留めを外す」）。
4. exe を削除する。
5. `%LOCALAPPDATA%\AIUsageBar\` を削除する（設定・集計キャッシュ・鍵・チーム参加状態・エラーログ）。
6. ポリシーを配布した場合は `SOFTWARE\Policies\AIUsageBar` を削除する。
7. チームを廃止する場合は、共有フォルダの `AIUsageBar-Team\` を削除する。

元の Claude Code・Codex・Claude Desktop のデータは変更しないので、削除する必要はありません。
